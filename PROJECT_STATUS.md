Обновлено: август 2026. Этот файл — для переноса контекста в новый чат с Claude, если текущий тормозит/переполнен. Прикрепи его вместе со свежими `main.py`, `static/admin.html`, `static/index.html` в начале нового разговора.

## Кто владелец и что это за проект

**Max** — самозанятый, сдаёт квартиру-студию посуточно в Новосибирске (ул. Дачная, д.5, кв.286, 22 этаж) под брендом **«Городская Пауза»**. Он не профессиональный разработчик, работает через Claude в чате, деплоит сам по SSH. Общение — на русском.

**Проект** — полноценная система бронирования и управления посуточной арендой:
- Публичный сайт (`citypause.ru`) — бронирование, оплата, договоры
- Админ-панель (`citypause.ru/static/admin.html`) — управление всем
- Backend на FastAPI (`main.py`, один файл, ~3800+ строк), SQLite (`/data/bookings.db`)
- Долгосрочный план (озвучен ранее) — white-label SaaS для других арендодателей, но пока в фокусе только этот один объект. Указывал, что перед white-label нужен рефакторинг `main.py` на модули + тесты — это ещё не начато.

## Инфраструктура

- **Хостинг:** свой VPS (не Railway — с него ушли из-за проблем с приёмом российских карт), Ubuntu, nginx + certbot (SSL Let's Encrypt, автопродление настроено и подтверждено рабочим), systemd-сервис `apart` (`WorkingDirectory=/app`, `Restart=always`, `EnvironmentFile=/app/.env`)
- **Деплой:** Max коммитит и пушит с локального Windows-компьютера (`C:\Users\HP\...\apart-project`) в GitHub, затем на сервере по SSH:
  ```bash
  cd /app && git pull && systemctl restart apart
  ```
  Это его привычная команда — **давать именно её**, без промежуточных шагов, если не нужна доп. диагностика.
- **Частые грабли за время работы:**
  - Забывает реально заменить локальный файл перед `git add`/`commit` (коммитит без изменений)
  - Забывает `systemctl restart apart` после `git pull` (Python не подхватывает новый код без рестарта)
  - Путает домашнюю папку (`~`) с `/app` при выполнении команд на сервере
  - Не путай его текущую директорию на локальном Windows-компьютере (там `cd /app` не нужен и ломается) с сервером (там нужен)
- **`.gitignore`** — создан недавно (раньше отсутствовал!), защищает `.env`, `.venv/`, `__pycache__/`, `/data/`, `*.db`, `*.log`. Секреты (`.env`) никогда не попадали в git — проверено через `git log --all -- .env`.
- **Telegram ненадёжен** — блокировки на уровне сети (видны таймауты в логах: `Bot polling error: Request timeout`), это внешнее ограничение, не баг. Email — основной надёжный канал уведомлений. Не тратить время на попытки "починить" Telegram-доставку глубже best-effort (`asyncio.wait_for(..., timeout=...)`).

## Ключевые модели данных (main.py)

- **Prices** — weekday, weekend, cleaning, included_guests, extra_guest_price, deposit, stay_discounts (4 порога {min_nights, percent}), holiday_periods (список {start, end, price, label} — фиксированная цена на период)
- **Contacts** — phone, email, telegram, whatsapp, max (мессенджер) — контакты ДЛЯ СВЯЗИ, отдельно от оплаты
- **PaymentSettings** — sbp_link, sbp_phone + отдельно загружаемый QR-код (файл) — для приёма оплаты, НЕ путать с Contacts
- **SiteSettings** — amenities (12 слотов), location_points (5 слотов: icon/name/distance/description — "ближайшие места" рядом с картой), nav_labels, nav_extra_label/url (доп. пункт меню — сейчас используется под "Скидки"), hero/logo настройки, map_photo/map_url
- **Discount** — акции/скидки на отдельной публичной странице (id, name, photo, description, visible) — CRUD как у Place ("Куда сходить")
- **bookings** (SQLite, `SELECT *` во многих местах) — ключевые поля: username (booking_ref, формат `GP-XXXXXX`), status, check_in/out, guest_name/phone/email, passport, guests_count, total_price, deposit, deposit_returned/deposit_returned_at, sign_token, signed_at, sign_ip, source (avito/yandex/sutochno/phone/other/external), created_at, confirmed_at

## Что реализовано (полная хронология этого чата)

### 1. Электронная подпись договора (ПЭП, 63-ФЗ)
- **Важно:** изначально обсуждали SMS-подписание, но отказались (проблемы с SMS-провайдерами и лишняя сложность) — **финальная реализация: подписание по персональной ссылке на email**, без SMS.
- Флоу для броней с сайта: гость бронирует → админ подтверждает оплату → письмо со ссылкой `/sign/{token}` → гость видит текст договора + согласия на ПД → нажимает «Подписать» (один клик = ПЭП) → получает подписанный PDF.
- Итоговый подписанный PDF — **один документ**: договор (с Приложениями 1 и 2, разрыв страницы перед ними) + Соглашение об электронном документообороте (адаптированный текст, упоминает citypause.ru вместо ОкиДоки) + 2 фото паспорта **с водяным знаком** («ЗАПРЕЩЕНО КОПИРОВАТЬ И ИСПОЛЬЗОВАТЬ ОТДЕЛЬНО ОТ ДАННОГО ДОКУМЕНТА», диагональный повторяющийся текст) + блок подписи в золотой рамке с логотипом «Г О Р О Д С К А Я  П А У З А». На каждой странице снизу справа — «Городская Пауза {id}. N / M» (нумерация страниц, как у ОкиДоки).
- Согласие на обработку ПД — **отдельный** второй PDF с тем же блоком подписи (свой doc_id).
- Оба письма (гостю) теперь **дублируются на почту Городской Паузы** из Контактов (добавлено недавно).
- Хэши подписи генерируются автоматически (`_sig_hash()`, SHA-256, детерминированно из данных сторон) — не нужно вписывать вручную.
- Телефон арендодателя в блоке подписи — берётся из Контактов (`get_landlord_phone()`), а не хардкожен.

### 2. Ручное бронирование (Авито/Суточно/телефон) + донаполнение данных
- Проблема, которую решали: площадки типа Авито часто не дают email/телефон гостя, только чат.
- Решение: в админке при ручной брони можно оставить пустыми **вообще все** поля кроме дат/суммы (ФИО, телефон, email, паспорт — всё необязательно).
- После создания брони — **копируемая ссылка** `/complete/{token}` (плюс письмо, если email всё же указан).
- Страница `complete.html` — гость сам донаполняет то, чего не хватает: ФИО (фамилия+имя обязательны, отчество — с чекбоксом «отсутствует»), телефон (маска +7, ровно 10 цифр), email (обязателен именно тут — некуда слать договор без него), паспорт (маска `0000 000000`), 2 фото паспорта, две галочки согласия → кнопка «Подписать».
- Если админ уже указал что-то (например паспорт) — это поле на странице гостя не показывается.
- Депозит — настраивается глобально в Тарифах, можно переопределить для конкретной ручной брони.

### 3. Блокировка дат в календаре (был серьёзный баг)
- Раньше кнопка «Заблокировать/Разблокировать» в админке писала только в `localStorage` браузера — не создавала реальной записи в БД, гости могли бронировать «заблокированные» даты. Исправлено: теперь реальные строки в `bookings` со статусом `blocked`.
- Отдельно нашли и починили рассинхрон: `/api/bookings` (публичный, для календаря сайта) использовал отдельный устаревший фильтр статусов, не совпадающий с `is_dates_available()` — из-за этого блокировки и статус `fully_paid` не считались занятыми на сайте.

### 4. Ценообразование
- **Доплата за доп. гостей** — настраивается в Тарифах (included_guests, extra_guest_price), считается **за сутки** (100₽/сутки/доп.гостя — уточнено явно, это НЕ разовая сумма). Показывается на сайте только при выборе гостей, не афишируется на главной.
- **Скидка за длительность проживания** — 4 настраиваемых порога (мин. ночей → %), автоприменение.
- **Праздничные дни** — неограниченное число периодов с фиксированной ценой за ночь (перекрывает будни/выходные), с необязательным названием периода.
- **Выходные дни** — важное уточнение от Max: выходная цена только для ночей Пт→Сб и Сб→Вс. Ночь Вс→Пн — уже будний тариф (это чинили, раньше воскресенье тоже считалось выходным).
- Депозит — настраиваемый глобально + переопределяемый в ручной брони.
- Итоговая разбивка стоимости — показывается ДВАЖДЫ на сайте (на шаге дат и на финальном шаге оплаты, обе версии синхронизированы): основная стоимость, скидка за срок, промокод, доп.уборка, доп.гости, итого, предоплата 20%.

### 5. Оплата
- Раньше — ссылка T-Bank «Сбор денег», которая перекидывала на страницу входа в личный кабинет (проблема). Заменено на: **QR-код (свой загруженный ИЛИ автосгенерированный из ссылки) + кнопка со ссылкой на оплату по СБП + номер телефона** — все три варианта независимо конфигурируются в админке, отдельная карточка «Оплата (СБП)» (НЕ в общих Контактах).
- QR и кнопка-ссылка — два равных квадрата рядом, телефон — отдельный крупный блок на всю ширину снизу.

### 6. Скидки и акции (отдельная фича, не путать с ценовыми скидками)
- Публичная страница `/static/discounts.html` — карточки с фото+описанием акций, управляются в админке (раздел «Скидки и акции», CRUD как у «Куда сходить»).
- Подключается к навигации сайта через уже существующий (просто раньше пустовавший) слот `nav_extra_label`/`nav_extra_url` в Настройках сайта — код трогать не пришлось, просто заполнить поля.

### 7. Резервное копирование
- Автоматически каждую ночь в 04:00: `bookings.db` + все JSON-настройки + **подписанные договоры целиком** + **фото паспортов целиком** (это чинили отдельно — изначально бэкапились только база+настройки, документы терялись бы безвозвратно при отказе сервера).
- Отправка: **Telegram (best-effort, часто не доходит из-за блокировок) + email** (на адрес из Контактов, фолбэк `citypause@mail.ru`). Защита от превышения лимитов: >50МБ не шлётся в Telegram, >20МБ может не пройти на почту — но копия всегда остаётся локально в `/data/backups/` (ротация, последние 14).
- Кнопка «Создать копию сейчас» в админке (Настройки) — эндпоинт `/api/admin/backup-now` работает в фоне (`asyncio.create_task`), чтобы не упираться в таймаут запроса браузера (это тоже был баг — чинили).

### 8. Мониторинг доступности (watchdog.sh)
- Отдельный bash-скрипт, НЕ в git, лежит прямо на сервере (`/app/watchdog.sh`), запускается через **cron** каждые 5 минут: `*/5 * * * * /app/watchdog.sh >> /app/watchdog.log 2>&1`
- Проверяет `https://citypause.ru/api/prices`, при сбое пробует `systemctl restart apart`, шлёт алерт в Telegram (токен и chat_id берутся из `.env`: `BOT_TOKEN`, `WATCHDOG_CHAT_ID`).
- Рекомендовал Max ещё подключить внешний UptimeRobot (для отказа всего сервера, не только приложения) — не уверен, сделал ли он это.

### 9. Дашборд админки — алерты + автообновление
- Карточка «⚠️ Требует внимания» (показывается только если есть алерты):
  - Оплата не подтверждена **>2 часов** (не суток — уточнено явно)
  - Нет фото паспорта — для **любой** активной/будущей брони без фото (не только «заезд завтра» — расширили по просьбе), с защитой от ложных срабатываний (пропускает неоплаченные, отменённые, заблокированные даты, уже завершившиеся)
  - Депозит не возвращён — подсвечивается **сразу после выезда** (не через неделю — тоже уточнили), с кнопкой «Депозит возвращён» прямо в алерте
- Автообновление списка броней и статистики дашборда каждые 25 сек в фоне (пауза, если вкладка неактивна) — чтобы новые брони с сайта появлялись без ручного F5.

### 10. Раздел «Расположение» на сайте

## Стиль работы с Max
- Общается по-русски, простыми словами, не разработчик — избегай жаргона без объяснения.
- Любит, когда сразу даёшь готовую команду для копипаста, без лишних объяснений «зачем».
- Часто тестирует сразу на проде (нет отдельного staging) — будь аккуратен с изменениями, затрагивающими уже работающие потоки (бронирование, оплата, подписание).
- Периодически путается в git/SSH-командах — если что-то не сработало, сразу переходи к пошаговой диагностике (`git status`, конкретные `grep`/`ls` проверки), а не гадай.
- Ценит, когда сверяешь актуальные файлы перед правкой (просить прислать свежие `main.py`/`admin.html`/`index.html`, если есть подозрение на рассинхрон) — несколько раз ловили ситуацию, когда рабочая копия Claude отставала от реально задеплоенного кода.
